## 关键核查事实

- 项目所有既有 partial unique index 迁移（0009/0024/0026/0035/0038/0043/0044/0048/0053）
  均同时写 `sqlite_where` + `postgresql_where`；0053 使用 `if bind.dialect.name` 方言分支。
- 迁移 0053 对必填列显式写 `nullable=False`。

## 结论：❌ 不通过

### 严重问题（必须修复，均在迁移文件）

1. 3 处 partial unique index 只写 `sqlite_where`，漏 `postgresql_where`
   （第 45/69/92 行）。PG 上方言参数被忽略，索引退化为全量唯一索引，
   同 code 第二条 is_active=False 记录（第二个版本）无法插入，多版本模型失效。
2. 所有非空列未写 `nullable=False`，alembic 默认 nullable=True，
   与 ORM `Mapped[非 Optional]` 的 NOT NULL 语义漂移。

### 重要问题

1. 测试仅元数据静态检查，缺写入级断言（双活插入应抛 IntegrityError、
   多版本 inactive 应成功）。
2. 测试未覆盖迁移与 ORM 的逐列一致性（正是严重问题 2 的漂移类型）。

### 轻微问题

1. `priority` 默认 999 为魔法数字，建议提常量。
2. `condition_relation` String(8) 偏紧，建议 String(16)。
3. `RuleDefinition.category` 无索引，与 IndicatorDefinition 不一致，按需补。
4. 建议 ORM 同时写 default + server_default。

### 优点

- 3 类与 IndicatorDefinition 风格完全对齐（Mapped 语法、__mapper_args__、字段顺序）。
- 命名规范统一（表名/约束/索引前缀）。
- 单活约束设计正确（partial unique index on (code, is_active)）。
- 测试正确 stop() IsolatedTestDatabase，优于参考样板。
- downgrade 安全（无外部 FK，倒序删表）。
